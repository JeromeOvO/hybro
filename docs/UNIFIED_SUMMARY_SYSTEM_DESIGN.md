# Unified Summary System Design

**Date:** 2026-04-04
**Status:** Approved
**Scope:** Backend summary/synthesis refactor + frontend display unification

## Problem

The current system has two independent summary mechanisms that produce messages after agents complete a user message turn:

1. **Supervisor Synthesis** — Generated by Bedrock Claude via `room_supervisor_service.synthesize_v2()` when supervisor V2 mode is active. Uses `agent_id="supervisor_synthesis"`, displays as "Agent" on frontend. Emitted via `room_coordinator_service.emit_synthesis_message()` from `RoomMessageCenter._handle_v2_run_result()`.

2. **Coordinator Summary** — Generated by OpenAI gpt-4o-mini via `openai_service.summarize_agent_responses()` after all agents complete, when >=2 non-empty agent responses exist. Uses `agent_id="non_debate_summary"` or `"debate_summary"`, displays as "Summary Agent" or "Debate Coordinator". Triggered via `room_coordinator_service.on_room_user_message_completed()`.

### Specific issues

- **Inconsistent frontend display**: "Agent", "Summary Agent", and "Debate Coordinator" for conceptually the same thing.
- **Fragile mutual exclusion**: A `synthesis_emitted` boolean flag in `_handle_v2_run_result()` controls whether the coordinator summary fallback fires. Edge cases can produce two summaries or none.
- **Dual placeholder SSE ownership**: `SupervisorExecutor` emits `synth-placeholder-{id}` (lines 665, 896), then `RoomMessageCenter` emits another `task_submitted` with a different ID (line 1369). Stuck spinners on cancel/failure.
- **No idempotency**: `_create_and_emit_summary_message()` blindly inserts a new `RoomAgentMessage`. Crash-then-retry can produce duplicate summaries.
- **6 `CoordinatorAgentId` values** with overlapping semantics scattered across the codebase.

## Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Summary count per turn | Exactly one | Users should see one coherent summary, not two |
| Frontend display name | "Summary Agent" (all paths) | Clear, consistent identity |
| Generation model | Dual: supervisor uses Bedrock Claude, non-supervisor uses OpenAI gpt-4o-mini | Supervisor synthesis is higher quality; no need to downgrade it through OpenAI |
| Trigger threshold | >=2 non-empty agent responses | Single agent response needs no summary |
| Prompt styles | Keep debate/non-debate variants | Different summarization goals per mode |
| Supervisor synthesis | Keep as internal artifact, display under unified "Summary Agent" identity | Content quality preserved, presentation unified |
| Non-summary CoordinatorAgentIds | Unchanged (SUPERVISOR_ERROR, SUPERVISOR_CLARIFY, SYSTEM) | Out of scope |

## Architecture

### New `CoordinatorAgentId` enum

```python
class CoordinatorAgentId(StrEnum):
    SUPERVISOR_ERROR = "supervisor_error"
    SUPERVISOR_CLARIFY = "supervisor_clarify"
    SUMMARY = "summary"                          # NEW — all new writes use this
    SYSTEM = "system"
    # Deprecated — kept for historical data backward compatibility
    DEBATE_SUMMARY = "debate_summary"
    NON_DEBATE_SUMMARY = "non_debate_summary"
    SUPERVISOR_SYNTHESIS = "supervisor_synthesis"
```

### Unified entry point: `_emit_unified_summary()`

New private method in `RoomMessageCenter`:

```python
async def _emit_unified_summary(
    self,
    room_id: str,
    user_message_id: str,
    *,
    synthesis_text: str | None = None,
    trajectory_responses: list[dict[str, str]] | None = None,
    is_debate: bool = False,
) -> None:
```

### Internal flow

```
1. Generate deterministic message_id = f"summary-{user_message_id}"

2. Send SSE task_submitted:
   - message_id = summary-{user_message_id}
   - agent_name = "Summary Agent"
   - agent_id = "summary"
   - status = "working"

3. Determine summary content:
   IF synthesis_text is not None:
       content = synthesis_text
       origin = "supervisor"
   ELSE:
       IF trajectory_responses provided:
           agent_responses = trajectory_responses
       ELSE:
           agent_responses = BFS collect from DB
       IF len(agent_responses) < 2:
           Send SSE task_update(status="completed") to dismiss placeholder
           RETURN
       content = await openai_service.summarize_agent_responses(
           agent_responses, mode="debate" if is_debate else "non_debate"
       )
       origin = "coordinator"
       IF content is empty:
           Send SSE task_update(status="completed") to dismiss placeholder
           RETURN

4. Build RoomAgentMessage:
   - message_id = summary-{user_message_id}
   - agent_id = CoordinatorAgentId.SUMMARY
   - related_message_id = user_message_id
   - extend_info = {
       "is_coordinator_summary": True,
       "source_user_message_id": user_message_id,
       "summary_type": "debate" | "non_debate",
       "summary_origin": origin,  # "supervisor" | "coordinator"
     }

5. DB upsert via replace_one({"message_id": message_id}, doc, upsert=True)

6. Send SSE agent_response

7. On ANY exception: send SSE task_update(status="failed") to clean up placeholder
```

### Single message_id lifecycle

The same `summary-{user_message_id}` is used for:
- The initial `task_submitted` placeholder (working spinner)
- The final `agent_response` (summary content)
- The DB document

No dismiss-then-create. No dual placeholder IDs. One ID from start to finish.

## Call Site Changes

### A. Supervisor V2 completion (`_handle_v2_run_result`, RunStatus.COMPLETED)

**Remove:**
- `emit_synthesis_message()` call
- `synthesis_emitted` flag
- Fallback `on_room_user_message_completed()` call
- `synth-placeholder-{id}` dismiss logic

**Replace with:**
```python
case RunStatus.COMPLETED:
    trajectory_responses = [
        {"agent_name": step.agent_name, "message": step.response_text}
        for entry in result.trajectory.entries
        if entry.action.action == ActionType.DELEGATE
        for step in entry.results
        if step.success and step.response_text
    ]
    await self._emit_unified_summary(
        room_id, user_message_id,
        synthesis_text=result.synthesis_text,
        trajectory_responses=trajectory_responses,
        is_debate=room_config.is_debate_mode if room_config else False,
    )
```

Note: `synthesis_text` may be None (debate fast-path where supervisor skips SYNTHESIZE action). In that case, `_emit_unified_summary` falls through to OpenAI generation using `trajectory_responses`.

### B. QueueExecutor completion (non-supervisor, line ~407)

**Remove:** `room_coordinator_service.on_room_user_message_completed(room_id, room_user_message_id)`

**Replace with:**
```python
is_debate = bool(room and room.extend_info and room.extend_info.get("debateMode"))
await self._emit_unified_summary(room_id, room_user_message_id, is_debate=is_debate)
```

### C. HITL resume completion (line ~1755)

Same replacement as B.

## SupervisorExecutor Changes

- **Keep**: `synthesize_v2()` call and `SupervisorRunResult.synthesis_text` return
- **Remove**: `synth-placeholder-{id}` SSE emission (lines ~665, ~896)
- **Remove**: Budget-path placeholder SSE emission

The supervisor still generates synthesis internally. It just no longer emits any SSE directly for the summary. That responsibility moves entirely to `_emit_unified_summary()`.

## RoomCoordinatorService Changes

- `on_room_user_message_completed()` — marked deprecated, no longer called from RoomMessageCenter
- `emit_synthesis_message()` — still used for `SUPERVISOR_ERROR` and `SUPERVISOR_CLARIFY` only
- `_collect_agent_messages_for_user_message()` — kept as utility, called by `_emit_unified_summary()`
- `_create_and_emit_summary_message()` — logic absorbed into `_emit_unified_summary()`

## BFS Filter Update

**Current** (`room_coordinator_service.py:119`):
```python
if msg.agent_id in ("debate_summary", "non_debate_summary"):
    continue
```

**New:**
```python
if (msg.extend_info and msg.extend_info.get("is_coordinator_summary")) or \
   msg.agent_id in (
       "debate_summary", "non_debate_summary", "summary",
       "supervisor_synthesis", "supervisor_error", "supervisor_clarify",
   ):
    continue
```

Filters all synthetic coordinator messages (not just summaries) to prevent re-summarizing system-generated content. Backward compatible with historical data that lacks `extend_info`.

## Database Changes

New method in `database_service.py`:

```python
async def upsert_room_agent_message(self, message: RoomAgentMessage) -> None:
    """Insert or replace a RoomAgentMessage by message_id. Idempotent."""
```

Implementation in `mongodb.py`:
```python
await self.room_agent_messages.replace_one(
    {"message_id": message.message_id},
    message.model_dump(by_alias=True),
    upsert=True,
)
```

MongoDB single-document operations are atomic. This prevents duplicate summary documents on crash-retry.

Note: SSE deduplication is a separate concern. If two workers race, both may emit `agent_response`. The frontend should dedupe by `message_id` (existing behavior for agent messages).

## Unchanged

- `SUPERVISOR_ERROR`, `SUPERVISOR_CLARIFY`, `SYSTEM` enum values and all their usage
- `openai_service.summarize_agent_responses()` with debate/non_debate prompt modes
- `room_supervisor_service.synthesize_v2()` Bedrock Claude synthesis generation
- `>=2` agent response threshold
- `debateMode` room-level toggle in `room.extend_info`
- `debate_service.py` short debate injection logic

## Test Impact

Tests in `tests/test_room_coordinator_service.py` and `tests/test_models.py` that reference old `CoordinatorAgentId` values or `on_room_user_message_completed()` need updating to use the new unified path. Specifically:

- Tests asserting `agent_id == "debate_summary"` or `"non_debate_summary"` should assert `"summary"`
- Tests calling `on_room_user_message_completed()` should call `_emit_unified_summary()` (or test through `RoomMessageCenter` integration)
- New tests needed for: idempotent upsert, placeholder cleanup on failure, synthesis_text passthrough vs OpenAI generation, BFS filter with mixed old/new data

## Migration

No data migration needed. Old documents with `debate_summary`, `non_debate_summary`, or `supervisor_synthesis` as `agent_id` remain readable:
- BFS filter handles both old and new IDs
- Frontend maps all old IDs to "Summary Agent"
- New writes always use `"summary"`
