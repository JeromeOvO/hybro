Hybro — local configuration and service CLI

Usage: hybro [command]
       ./scripts/hybro [command]   (from a source checkout)

A released install runs the published images pinned to its own version, so
`hybro --version` is also the version of the stack it starts. From a checkout,
--build and --compose-file operate on the local sources instead.

No command opens the Models/Services TUI when a terminal is available.
Non-interactive use without a command prints this help.
The TUI is centered and uses the frontend's cyan selection color. Its blue nested
cubes expand/contract through each other at a fixed angle, without rotation.
The logo loops while menus wait for input; Space pauses/resumes animation.
Compact terminals omit the logo to preserve controls. No animation runs during commands.
The Services page offers Start, Stop, Reload configuration and View logs.
Above Start services, each long-running service shows green active or red inactive.
One-time setup jobs are omitted. The row wraps on narrow terminals.
Status refreshes on entry and after actions; no background polling.
Reload configuration confirms before recreating containers.
View logs selects one container or All; Ctrl-C returns to the container picker.
Advanced lifecycle commands remain available below.

Configuration:
    setup
        Select Provider/authentication, authenticate, choose models, verify text,
        and save config.json/auth.json. Requires uv and an interactive terminal
        for browser OAuth or hidden API-key input. One text verification request
        uses API billing or subscription quota; images are never probed.
        OpenAI supports API Key or ChatGPT OAuth; DeepSeek and Anthropic use keys.
        OAuth does not enable image generation.
        Explicit automation flags remain supported; run setup --help for details.
        Environment API keys are one-time setup inputs and are saved privately;
        running services do not read Provider keys from environment files.

    config show
        Show user configuration only, never auth.json credentials.
    config check
        Check configuration/credential structure without Provider calls.
    config set <path> <JSON-value>
        Validate and save a deployment setting. Example:
            ./scripts/hybro config set backend.log_level '"DEBUG"'
            ./scripts/hybro config set frontend.max_message_length 12000
        Use setup, not config set, for Provider/model changes.
    config secret <name>
        Set a service credential using hidden terminal input.
    config migrate [--from-env <legacy-file>]
        Explicit one-time conversion of config.yaml to config.json. Optional
        --from-env imports known deployment settings/credentials before you
        remove the old files. Does not delete originals or overwrite config.json.

Services:
    start [--build] [--recreate] [--compose-file <file>]
        Validate setup, generate missing private service tokens, regenerate the
        default-agent Compose region in a checkout, and start services. No dotenv
        file needed.
        --build rebuilds images; only a source checkout can build.
        --recreate recreates existing containers; use it after changing
        configuration. A released install needs --recreate, never --build.
        --compose-file adds an explicit overlay beside the stack, for example
        docker-compose.ci.yml for the CI mock-LLM stack. It is passed to Compose
        directly; no ambient Compose discovery is used.
    status | ps
        Show all containers, including stopped containers.
    logs [service...]
        Follow logs. Ctrl-C stops following logs.
    logs --container <name>
        Follow one exact container, including a specific replica, from its last
        100 lines. The TUI also limits All to 100 initial lines per container.
    stop
        Stop containers without deleting them.
    restart [service...]
        Restart existing containers. Use start --recreate to apply new projections.
    down [Docker arguments...]
        Remove containers/network. Named volumes remain unless -v is supplied.
    help | --help | -h
        Show this help.
    --version | -v
        Print the CLI and stack version.
    upgrade [--check]
        Install the newest published release. The container images are pinned to
        the CLI version, so upgrading the CLI is what moves the stack; finish
        with hybro start --recreate. An npm install is replaced in place; a
        release-archive install prints the download and checksum commands
        instead, because hybro does not overwrite its own directory. --check
        only reports, and exits non-zero when a newer release exists.
        A source checkout is updated with git pull, not by this command.

Files:
    HYBRO_HOME/config.json  — user overrides, shared by backend and frontend.
    HYBRO_HOME/auth.json    — Provider/OAuth and scoped service credentials.
    HYBRO_HOME defaults to ~/.hybro and must be absolute when overridden.
    The directory is private (0700); auth.json requires mode 0600.
    Missing setup or invalid JSON fails explicitly; no legacy Provider fallback.
    Edit through the CLI or edit config.json directly. Changes apply after restart;
    public frontend build changes also require --build. No hot reload.

Docker is launched through this CLI so only scoped JSON-derived values reach each
service. Agents never receive Provider credentials; frontend builds never receive
server credentials. Existing .env/.env.example files are not deleted automatically.
